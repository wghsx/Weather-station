# 智能气象站（STM32F103）

基于 STM32F103 的桌面气象终端：支持语音提问天气、语音播报室内温湿度、LCD 实时显示。语音识别、语音播报、WiFi 联网三条链路并行工作。

## 功能

- **语音交互**：识别模块拾取语音指令，本地解析后驱动播放模块应答，形成「识别—决策—播报」闭环
- **天气查询**：经 ESP8266 连接天气接口，HTTP 拉取实况天气，解析后转语音播报
- **环境监测**：DHT11 采集温湿度，SysTick 每 2 秒刷新一次屏幕
- **本地显示**：ST7789 屏显示标题、温湿度数值与图标
- **按键与指示灯**：PA0 按键配合外部中断，PC4/PC5 双色指示灯

## 通信协议

### 语音识别模块上行帧（UART4）

4 字节定长：`AA BB ID CC`

| 字节 | 含义 |
|---|---|
| 0 | 帧头 0xAA |
| 1 | 帧头 0xBB |
| 2 | 指令 ID |
| 3 | 帧尾 0xCC |

| ID | 指令 | ID | 指令 |
|---|---|---|---|
| 0x01 | 唤醒 | 0x06 | 停止播放 |
| 0x02 | 身份询问 | 0x07 | 开灯 |
| 0x03 | 室内温度 | 0x08 | 关灯 |
| 0x04 | 室内湿度 | 0x09 | 天气查询 |
| 0x05 | 播放音乐 | | |

### 语音播放模块下行帧（UART5）

7 字节：`7E 05 42 DIR NUM CHK EF`

`CHK = 0x05 ^ 0x42 ^ DIR ^ NUM`，接收端按异或校验和验证。

## 关键技术点

**双路语音链路**：两路串口各走一套协议，上行 4 字节定长帧解析指令，下行 7 字节带校验帧控制播放。温度播报时将浮点数拆为整数位、小数位与单位，分段调用语音文件，避免逐条录音。

**不定长数据接收**：USART3 与 UART4 均启用 RXNE + IDLE 双中断。RXNE 逐字节入缓冲，IDLE 判定一帧结束，在中断中读 SR/DR 清除标志后置帧完成位。相比在中断里做完整解析，这种方式把协议处理交回主循环，中断停留时间更短。

**AT 指令时序控制**：ESP8266 初始化按 `CWMODE → CIPMODE → CWJAP → CIPSTART → CIPSEND` 顺序下发，每步等待模块回 `OK`，超时返回失败并终止流程，避免在模块未就绪时继续下发导致状态错乱。

**天气接口解析**：HTTP GET 拉取实况数据后，用 `strstr` 匹配 JSON 字段 `numtq` 提取两位天气代码，映射到 18 种天气类型，再触发对应的语音播报。

**DHT11 单总线时序**：起始信号拉低 20 ms，释放后检测模块响应，随后按高电平持续时间区分 0/1 读取 40 位数据，最后比对校验和。

## 编译与运行

1. Keil MDK 打开 `project.uvprojx`，选择 STM32F103 器件
2. 编译前先完成下一节的配置
3. 下载到开发板，复位后调试串口（USART1，9600）会打印初始化日志

## 使用前配置

`system/wifi.c` 中三处占位符需替换为本机实际值，否则联网与天气查询不可用：

| 占位符 | 位置 | 填写内容 |
|---|---|---|
| `YOUR_WIFI_SSID` | 约 182 行 `AT+CWJAP` | WiFi 名称 |
| `YOUR_WIFI_PASSWORD` | 约 182 行 `AT+CWJAP` | WiFi 密码 |
| `YOUR_API_KEY` | 约 217 行 HTTP GET | 天气接口申请的 key |

仓库中不包含任何真实凭据。天气接口使用第三方免费服务，需自行注册获取 key，接口地址与城市 ID 也在同一行，可按需替换。

## 已知问题与改进方向

- 天气代码判断为 18 个并列 `if` 串联，可改为提取数字后 `switch` 或查表映射，代码量能压缩一个数量级
- AT 指令失败后直接返回，没有重连与重试机制，实际使用中建议增加状态机与断线检测
- HTTP 响应依靠关键字匹配判断有效性，未按 `Content-Length` 收满，网络异常时可能误判
- 语音识别与播放模块共用同一套串口中断框架，后续可抽成统一的帧解析层
